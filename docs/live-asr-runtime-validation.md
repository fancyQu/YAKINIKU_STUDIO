# 直播本机 ASR 适配层验证记录

验证日期：2026-10-30（北京时间）。此记录只覆盖本机识别层；直播业务、网络翻译、字幕显示的验收须另行记录。

## 实现

- `yakiniku/model_runtime.py` 提供进程单例，模型加载、预热和推理由同一专用 worker 顺序执行。异步调用被取消后，底层原生任务继续占用该 worker，后续任务不能同时进行 GPU 推理。
- 所选模型必须在录制前加载并预热。MLX 权重在准备阶段流式计算 SHA256，并与已有来源记录校验；不匹配会在加载前失败。缓存引擎保留加载时的来源记录，修改磁盘 manifest 不会伪装已加载模型版本。文件存在只表示权重已准备；GPU 检查、加载或预热失败均不会显示为已就绪。
- MLX 只传已验证的绝对本地路径，使用离线模式、日语 `transcribe`，不传不支持的 `beam_size` / `vad_filter`。
- 正常无语音标记为 `no_speech`；有声但空结果、异常重复结果标为失败，保留音频供业务层重试。不会将错误说明作为字幕。
- Small、Turbo 和 Tiny 是明确的选择，模型缺失时不下载、不静默切换。Tiny 保留原 CPU 兼容环境。
- 双击启动脚本优先使用已准备的 `.venv-mlx`；直接运行可使用 `.venv-mlx/bin/python run.py`。

## 自动验证

`tests/test_model_runtime.py` 的 19 项测试在 Python 3.12 MLX 环境和原 Python 3.9 环境均通过，覆盖实际预热前不能推理、模型复用、取消后串行执行、有界任务提交、重复准备合并、加载错误、原生崩溃、无语音与异常空响应、异常重复输出、权重校验、缓存来源固定及旧 Tiny 来源记录等行为。同模型崩溃后重新准备会先关闭旧引擎，再加载替代；新引擎预热失败或权重校验失败后不残留就绪引擎。GPU 实测也确认了接口参数可以运行。

## 同一录音前 60 秒的离线分段基线

环境与固定权重来源沿用 [MLX 准备记录](mlx-local-setup.md)。以下调用经过新增的生产适配层，不经过独立 smoke-check 示例；没有调用翻译服务或上传音频。报告只保存计数、状态和耗时，不包含转写文字。

| 指标 | Small，3 秒段 | Small，5 秒段 |
| --- | ---: | ---: |
| 冷准备（含权重 SHA256、GPU 检查与静音预热） | 1.636 秒 | 1.905 秒 |
| 音频总长／片段数 | 60 秒／20 | 60 秒／12 |
| 成功有字片段 | 17 | 10 |
| 确认无语音 | 1 | 0 |
| 失败 | 2 | 2 |
| 成功识别耗时 P50 | 219 ms | 243 ms |
| 成功识别耗时 P95 | 264 ms | 397 ms |
| 全部尝试耗时 P95（含失败与无语音） | 260 ms | 1,002 ms |
| MLX 分配峰值 | 1,226,167,210 字节 | 1,226,232,746 字节 |
| 进程 RSS 峰值 | 883,736,576 字节 | 936,525,824 字节 |

5 秒方案的一段有声空返回和一段异常重复结果被保留为失败；重复结果的 compression ratio 约为 35，已防止其进入正式字幕。3 秒方案也有两段空返回，不能因耗时较短便认定质量更好。

原始统计：`data/diagnostics/live-mlx-small-3s.json` 和 `data/diagnostics/live-mlx-small-5s.json`。

复现命令（仅本地 PCM16 WAV；可替换为自己的音频路径）：

```sh
.venv-mlx/bin/python scripts/benchmark_live_asr.py \
  --audio data/recordings/92d1044a56f5478f9e2354a5457f3ce7/audio.wav \
  --seconds 60 --segment-seconds 5 \
  --report data/diagnostics/live-mlx-small-5s.json
```

将 `--segment-seconds` 改为 `3` 可重复对照；添加 `--pace` 会按照音频播放速度提交片段，可用于后续长时间稳定性测试。

## 尚未证明的事项

这不是完整直播的延迟或准确率验收。没有人工日语对照、真实翻译网络耗时、10 分钟连续讲话和 30 分钟实际稳定性记录。P95 来自小样本，且成功耗时与全部尝试耗时分别列出，不能用成功样本掩盖失败任务。Turbo 权重尚未准备，本轮未下载，也没有证据表明 Small 是最终最优默认模型。
