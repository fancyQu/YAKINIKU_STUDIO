# 直播录音精准校验

已保存直播可以从 `/static/preview.html?id=<id>` 显式提交完整录音重做。流程复用文件处理适配器：MiniMax `/speech_to_text` 识别日语，独立 GPT 请求保守校对 `ja_raw`，再翻译校对后的 `ja` 为中文。三种 SRT、文稿和预览 WAV 保存到独立子项目目录；原直播目录不写入任何链接或修改。

## 本机接口

| 接口 | 行为 |
| --- | --- |
| `GET /api/sessions/{id}/refinement` | 只读检查录音、已保存配置、现有子项目与处理锁；不调用第三方 |
| `POST /api/sessions/{id}/refine` | `{ "consent": true }`，创建并调度独立精修项目；重复请求返回现有项目 |
| `POST /api/imports/{child_id}/retry` | 继续中断或失败的精修项目，保留检查点 |

录制、导入、补全字幕或模型准备期间禁止启动其他精修任务。仅 `completed/partial/interrupted` 的已保存直播允许开始，原导入项目不显示此入口。子项目在既有音频项目列表可见，可使用已有预览和下载 API。

## 保存与恢复

- `refinement_source_id` 与 `refinement_source_parts` 标明来源 WAV 分卷及格式、大小和修改时间，不包含录音正文。
- 所有源文件通过 `SessionStore` 的编号和文件名白名单读取；缺失、截断、符号链接、不完整分卷或准备后发生变化的源文件被拒绝。
- 本机解码按分卷顺序有界读取，重采样为精修项目的 48 kHz 双声道 WAV，可自动分卷。只识别副本转为单声道 16 kHz、120 秒窗口，不将完整录音载入内存。
- 解码重试仅清理子项目生成的 WAV。已完成解码的子项目可独立继续处理。识别每块完成立即保存检查点，校对后先保存原文再请求翻译。
- `refinement_snapshot` 只保存允许的连接引用、模型、协议/地址指纹和术语表。重试继续解析原连接，允许密钥轮换和其他任务路由改变，不允许向改变地址或协议的连接静默继续发送。
- 服务重启按既有导入恢复逻辑标记 `interrupted`；不自动上传、重跑或创建重复项目。

## 验证范围

`tests/test_refinement.py` 使用合成音频和本机适配器覆盖三阶段调用、多卷与非 48 kHz 音频、原始文件字节保留、幂等、并发互斥、失败续跑、重启恢复、快照与凭据边界、源文件异常。`tests/preview-refinement.test.cjs` 覆盖用户明确提交、上传提示、状态轮询和已有结果入口。测试不会上传真实录音或产生服务商费用。

此功能是重新识别和生成字幕，不提供人工审校、逐字强制对齐或准确率保证。现有 MiniMax 适配器对仅文本响应继续使用明确标注的估算时间轴。本轮没有对真实用户录音进行云端精修验收；界面「配置就绪」仅指必要字段已保存，不代表服务账户和模型经过真实请求验证。
